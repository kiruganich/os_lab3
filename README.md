# Лабораторная работа 3, вар 10.

`gauss` — программа на C17 для Linux: решает систему линейных уравнений методом
Гаусса с выбором ведущего элемента по столбцу. Прямой ход выполняется в
нескольких потоках POSIX; их число задаётся обязательным ключом `-t` и ровно
столько потоков работает одновременно. Потоки синхронизируются барьером
`pthread_barrier_t`. На Windows программа работает внутри WSL2, не через MSVC.

## Структура

- `common/` — коды возврата, вывод ошибок, разбор числовых ключей;
- `os/` — потоки, барьер, часы, идентификаторы;
- `src/gauss/` — система уравнений, алгоритм, программа;
- `examples/system4.txt` — пример системы 4 × 4;
- `tests/smoke_test.sh` — 12 сценариев, 46 проверок;
- `tests/bench.sh` — замеры времени, ускорения и эффективности;
- `tests/threads_demo.sh` — потоки работающей программы в `ps`, `/proc`, `top`;
- `logs/` — журналы запусков;
- `docs/` — исходники отчёта и PDF; `docs/inc/` — копии для листингов и графиков.

## Сборка и запуск

В Ubuntu:

```bash
sudo apt update
sudo apt install -y build-essential cmake strace procps
```

Из корня репозитория:

```bash
make
make test
./build/gauss -t 2
```

Без `-g` система читается со стандартного ввода: размер n, затем n строк по
n + 1 числу `a1 ... an b`. Если ввод идёт с терминала, программа спрашивает
размер и каждую строку:

```text
$ ./build/gauss -t 2
size of the system n: 2
row 1 of 2 (a1 ... a2 b): 1 1 3
row 2 of 2 (a1 ... a2 b): 1 -1 1
...
2
1
```

Файл подаётся перенаправлением: `./build/gauss -t 4 < examples/system4.txt`.
Решение выводится в stdout по одному числу в строке; PID/TID, время и невязка
`max|Ax − b|` — в stderr.

| Ключ | Назначение |
|---|---|
| `-t <число>` | потоков одновременно, 1..256 (обязательный) |
| `-g <n>` | решить случайную систему n × n (для замеров), n ≤ 10000 |

У случайной системы `b_i` — сумма строки, поэтому точное решение — все единицы.
Решение такой системы не печатается. Сборка — Release (`-O3`): программа
исследуется на скорость. Время измеряется только для решения.

Число потоков во время работы:

```bash
./build/gauss -t 4 -g 3000 &
ps -L -o pid,lwp,nlwp,psr,stat,comm -p $!
grep Threads /proc/$!/status
```

## Логи

```bash
mkdir -p logs
set -o pipefail
make test 2>&1 | tee logs/tests.txt
bash tests/bench.sh build/gauss | tee logs/bench.txt
bash tests/threads_demo.sh build/gauss 4 3000 2>&1 | tee logs/threads.txt
script -q -e -c './build/gauss -t 3 < examples/system4.txt; ./build/gauss -t 6 -g 2000' \
    logs/demo.txt
strace -f -o logs/strace.txt -e trace=clone3,futex,exit ./build/gauss -t 3 -g 3
```

Эти команды перезаписывают соответствующие журналы. Замеры идут несколько
минут; каждая точка — медиана пяти запусков. Во время замеров компьютер не
должен быть занят другими задачами, иначе ускорение занижается.

## Отчёт

Текст редактируется в `docs/src/*.tex`, титульный лист — в `titlepage.tex`.
После изменения кода или журналов обновите копии в `docs/inc/`: графики
строятся pgfplots прямо из `docs/inc/bench.txt`.

Зависимости Ubuntu:

```bash
sudo apt install -y texlive-latex-extra texlive-lang-cyrillic \
    texlive-lang-greek texlive-fonts-recommended texlive-fonts-extra
```

Последний пакет имеет большой размер. pgfplots входит в `texlive-pictures`,
который ставится вместе с `texlive-latex-extra`. Сборка из корня:

```bash
make -C docs
```

Результат — `docs/report.pdf`. PDF пересобирается дважды для ссылок.
Номера строк во фрагментах кода (`literature.tex`) нужно сверить после
изменения `docs/inc/*.c`.

## Коды возврата

| Код | Причина |
|---|---|
| 0 | успех |
| 2 | неверные ключи запуска |
| 3 | ошибка чтения или формата системы |
| 4 | ошибка записи решения |
| 5 | матрица вырождена: нет единственного решения |
| 6 | ошибка создания потока или барьера |
| 7 | недостаточно памяти |
